# Blank: Project

(Formerly "Prism Plaza". The localStorage key `prismplaza.v1` and IndexedDB name `prismplaza` keep the old name on purpose so existing saves still load.)

Browser gacha game, built step by step. A **Vite** project in plain JavaScript (no framework):
- `index.html`: the page markup (title screen, menu, HUD, plaza canvas).
- `src/styles/main.css`: all styles except Card Clash, which lives in `src/styles/clash.css` (imported after main.css). `src/styles/ui2.css`: the **UI refresh layer**, imported after it in `src/main.js` (look only, see "UI refresh" below). `src/assets/fonts/Cinzel-Bold.otf`: the owner's font.
- `src/game/NN-name.js`: the game code, split by feature (`01-core` media/icons/state, `02-art` chibis, `03-ui` menu/title/loading, `04-modals`, `05-collection`, `06-pets`, `07-shop`, `08-profile`, `09-bond`, `10-economy` tickets/stamina/spin, `11-characters`, `12-gacha`, `13-admin`, `14-routing`, `15-plaza`, `16-backend`, `17-boot`, `18-net`, `19-farm`, `20-inventory`, `21-events`, `22-level`, `23-raids`, `24-scratch` scratch cards + bulk gifting, `25-mystery` Mystery Fountain, `26-fusion` clothes fusion + pets on characters, `27-score` CS, `28-quests` daily + weekly quests, `29-expedition` the Base's Expedition tab, `30-membership` monthly memberships, `31-camp` the Base's Camp tab, `32-potential` the character Potential boards, `33-memview` memory star frames + hold-to-view, `34-upgrade` pick-the-copy upgrade popup, `35-vip` VIP levels, `36-ranking` Ranking + 6★ borders, `37-honor` Pearl Honor battle pass, `38-rarity` coloured UR / SSR words, `39-petgrade` pet grades, `40-house` the House tab, `41-guild` guilds, `42-friends` the friend list, `43-offers` special offers incl. the First Top-Up, `44-clash` the Card Clash cards + rules engine + bot, `45-clash-ui` the Deck tab and Quick match board, `46-clash-art` the card emblems + metal / crystal gradients + card backs, `47-clash-fx` the match animations and particles, `48-clash-auto` the Card Clash auto play planner, `49-clash-rules` the illustrated How to play book). `vite.config.js` joins them **in name order into one module** (`virtual:game`), so they share one scope like the old single script: any file can use any top-level name, and order only matters for code that runs at load time. New files need an `NN-` prefix.
- In dev (`npm run dev`) every top-level name is also on `window` (for the console and Playwright tests); production builds don't expose them unless built with `VITE_DEBUG_GLOBALS=true`.
- `npm run build` → `dist/` (relative paths, works on any static host). `.github/workflows/deploy.yml` publishes `main` to GitHub Pages.
- **Server (optional):** Supabase, configured by `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` (`.env.local`, or repo secrets for the website; see README.md). Without them the game is fully local (`CLOUD_CONFIGURED`, `Backend.on` false). Schema + row-level security: `supabase/migrations/0001_init.sql`. Every new feature must keep working offline.

## How we work
- Windows (wide ones are capped to the screen and scroll inside: `.modal-back.is-wide{grid-template-rows:minmax(0,1fr)}`; all share the Settings look: blurred see-through backdrop `.modal-back`, title pill with a round badge `.inv-title`/`.inv-badge`, round close `.inv-x`): `openModal({ wide: true })` = full-screen window with no box, like Settings (`.modal-back.is-wide`), for menus (mail, achievements, collection, pets, admin, rates, notices, support, templates); default = medium (profile, daily spin, sign in, buy pulls, stamina, redeem; spin/profile get their own widths via `.modal-back[data-kind=…]`); `small: true` = quick confirmations. Scale content for the big size with `.modal.wide …` rules.
- The owner adds features in small batches. Put code in the matching `src/game` file (or a new numbered one).
- After changes: `npm run build`, then republish the claude.ai preview from `dist/index.html` with the files in `dist/assets` (not the `.map`) to https://claude.ai/artifact/VfWWApTnq9EfCShmKhxcQu. The preview has no server, so it runs offline with bots.
- Test in a browser with Playwright against `npm run dev` (top-level names are on `window` there).
- **UI refresh** (`src/styles/ui2.css`, after the owner asked for a gacha-style UI pass inspired by Genshin / Star Rail / Wuthering Waves / ZZZ, without copying): **the character screen (`.cs`) must stay exactly as it is** (the owner's rule), so every shared rule in ui2.css that could reach it is scoped with `:not(.cs *)` (scrollbars with `:where(:not(.cs):not(.cs *))` so specificity stays 0); a pixel diff of all 9 character tabs before/after was identical. The layer only changes looks and layout: crystal-rimmed HUD orbs (`--u2-ring`), the **bottom icon dock** (`.hm-tabs` centred between the gates and Summon; each `.tabb` = a diamond icon frame `.tbi` + label `.tbl`; icons `chars`, `paw`, `farm`, `home`, `book`, `cards` (the last two new in `ICONS`); fixed tile widths 96 / 82 / 70 px by window width, full-width dock under 1000 px), one capsule style for currencies (`.cur[data-k]`), crystal window headers (diamond after `.inv-title`, conic ring on `.inv-badge`, `.inv-x` turns on hover), glass toasts with a diamond, calmer red dots, press feedback, a soft open animation on full-screen screens (`u2Screen`; they are created on open so it plays once), one crystal **selection** look for event list / shop sidebar / mail / banner tabs, a hairline on medium modals, **quest cards get a progress bar** (`.dq-pbar`, also Pearl Honor missions), and the **7 Daily Login days fit in one row** on wide boards (container query on `.tl`). **Phones held sideways** (`@media (max-height:500px) and (orientation:landscape)`, tested at 932×430, 844×390, 740×360, 667×375) get compact layouts so nothing overlaps: home (ticket pills hidden there, they stay on the summon screen; dock labels hidden below 700 px), summon (banner list scrolls), events (list left, event scrolls right), quests, mail, ranking, shop Hot Picks, compact window headers. Medium windows (821–1240 px) wrap the top-right row instead of covering the name. A Playwright overlap check of the home HUD passes from 360×740 to 1920×1080. Tokens: `--u2-rim`, `--u2-rim-hi`, `--u2-panel`, `--u2-hair`, `--u2-ease`, `--u2-ring`.
- Keep the visual style: dark frosted-glass UI (tokens in `:root`). **Main action buttons use the crystal palette** from the owner's reference art (pale pink → rose → lavender → ice blue with deep indigo text: `--cry-grad`, `--cry-grad-h`, `--cry-ink`, `--cry-glow`, `--cry-edge`), not yellow: `.btn.gold`, the Summon buttons (`.summon2`, `.sx-pull.gold`), shop Buy (`.mall-go`, `.mall-buy.ok`, `.sx-btn.gold`), the event wish button (`.mb2-go`), quest Claim / tabs / checks / reward nodes and the Participation badge. Font: **Cinzel Bold** (the owner's file, embedded as base64 in `@font-face`) for all UI text via `--display`/`--body`; Nunito (`--read`) only for longer readable text (descriptions, `.tiny`, paragraphs, inputs, chat).

Note: two Defensive decks against each other tend to stall into the round-40 draw (balance item from the document, untested v2.1 cards). **The bot is deterministic:** its small randomness comes from a hash of the match state (`ccNoise(G, i)`), not `Math.random`, so the same seed + the same moves always replay the same match (auto play relies on it). `ccClone` is a fast hand-written copy (card objects are shared, units / boards / hands / piles copied; ~7× faster than `structuredClone`). **Auto play** (`48-clash-auto.js`, the **Auto** button in the match's top-right tools, `#ccAuto`, On / Off saved in `S.cc.auto`; the action panel shows "Auto play is on · Planning the turn… / Playing your turn… / Waiting for the bot…" with **Stop auto play**; touching a card yourself drops the current plan): plays your turns and is built to beat the bot. Unlike the bot it reads the whole match (the bot's hand, its face-down traps, both deck orders). Each of your turns: a **beam search** over whole action sequences (`ccAutoTurn`, `CC_AUTO {beam 10, depth 12, reply 12, horizon 16, lateExtra, endExtra}`, positions deduped by `ccAutoKey`, scored by `ccAutoEval`: hero HP with the enemy's HP weighing more each round, unit values, open lanes / threat (`ccAutoThreat`), a damage race clock, focus on the weakest enemy lane, late-game pressure on the enemy board), then the most promising endings (plus the cheap policy's own pick, so it can only improve) are **played forward exactly**: the real bot's answer (`ccAutoReply`) and auto play's cheap turns (`ccAutoBase` / `ccAutoRollout`) for 16 rounds; best future wins (`ccAutoScore`: a win, sooner = better; a draw only before a loss). **When no win is in sight it thinks much harder** (a 3× wider search of the turn, every future played to the end with a stronger policy). `ccAutoPlanGen` is a generator: `ccAutoPlan` runs it at once (tests), `ccAutoPlanAsync` yields to the browser every 12 ms with a **9 s thinking budget** per turn (`o.budget`, keeps the best plan so far). The UI runs it from `ccAutoSchedule` / `ccAutoStep` (waits for each animation, follows the plan while it stays legal, plans again otherwise). Tested in Node (vm harness over 44 + 48) against the real bot: Balanced mirror 40 / 40 wins, Rush mirror 40 / 40, 30 random 30-card decks 30 / 30; the Defensive mirror (the slow stalemate deck) wins far more than it draws and has not lost (see the latest report for the exact count). **Every win pays 1 pearl** (`CC_WIN_PEARLS`, added in `ccEndScreen`, shown as "+1 pearl for the win" in the results box; also on Rematch; with auto play winning it is farmable, no daily cap yet). **The bot is a random character from the game** (`startClash` picks a non-MC character from `S.pool` by the seed, `ccM.foe`): its name on the hero plaque and in the log, its round icon as the bot's portrait (`ccFoeAva`, `baseThumb`), its base splash art on the VS intro (`baseArt`; the hooded bot icon only when the pool has no characters). **How to play** (`49-clash-rules.js`, `ccRules(page)`, wide modal kind `ccrules`; opened by the match's **?**, the Deck screen's **How to play** button `#ccdHelp` and Quick match's link `#ccqHelp`): **13 illustrated pages** (`CC_RULES`: Goal, The board, Your turn, Reading a card, Units, Attacking, Moving, Spells, Traps, Equipment, Keywords, Limits & Overtime, Auto play) with numbered tabs, Back / Next and dots; every page pairs a picture built from the real game pieces (real cards via `ccCardHTML`, mini unit tokens `ccrUnit`, slots, lanes `ccrLane` with animated dashed arrows `ccrArrow`, a mini board with numbered pins `ccrBoard`, AP crystals, keyword chips) with the text; the icon credit sits on the last page. On phones the tabs become one scrolling row (the active tab scrolls into view) and the pictures shrink (`zoom`); sideways phones keep picture + text side by side. **Board details:** a table rim round the board (`.ccb-rim`: dark lacquer with gold inlay lines, a row of gold rivets top and bottom, four pulsing crystal studs at the side midpoints `.ccb-stud`), a faint crest watermark in each half (`.cc-crest`: crystal for you, the bot emblem in blood red), a strip of glowing rune script along each half's battle-line edge (`.cc-runes`, `--cc-glyphs` SVG mask, slowly scrolling and shimmering), a gold light sweeping round each half's trim (`.cc-sheen`, a border-only mask), crystal gems on the battle line at the three lane centres (`.ccb-gem`, red on the bot's turn) and slow light beams + low fog in the hall (`.ccm-ray`, `.ccm-fog`); all stop under reduced motion.

## Data
- `S` holds everything in memory but is saved in two parts (`splitState`, `persist`, `01-core.js`):
  - **content** (`CONTENT_KEYS`: pool, featuredId, banners, clothes, memories, titleNews, loadArts, media, farmLayout, events, fakeArts, upArts, mystery) = what the admin makes, shared by all players. Local key `prismplaza.content.v1`; online it is the single row of table `game_content` (admins write, everyone reads; pushed by `Backend.contentChanged` → `pushContent`, loaded at boot by `applyContent`).
  - **player save** = everything else. Local key `prismplaza.v1` (older saves that also hold content still load); online the `saves` table, one row per account (`pushSave` 2.5 s after changes; at sign-in the cloud save wins unless this browser has newer progress for the same account (`S.savedAt`), loading it writes localStorage and reloads).
  - When adding new shared admin data, add its key to `CONTENT_KEYS`; player progress needs nothing.
- Images: always go through `mediaSet(key, dataUrl)` / `mediaDel(key)`. They are cached in IndexedDB (`prismplaza`/`media`) and, for admins online, uploaded to the public Storage bucket `media` (key `art:aria` → path `art/aria`); `S.media` is the manifest `{key: version}` other players use to build the URLs (`applyMediaManifest`). Refer to images as `idb:<key>` and read them with `artFrom` / `MEDIA.get`.
- In the claude.ai preview (no server), `mediaSet` stores images in the preview's own file storage (artifact `assets` capability, `previewAssets()`): the manifest value is `a:<asset id>` and the image is served from `/_blob/<id>` (`assetSrc`, mapped at boot). The preview is published with capabilities `downloads` (full backup file) and `assets`. Failures show an error toast (`toast(msg, true)`), which ordinary toasts don't cover for 6 s.
- Full backup (`exportData`, format `blank-full-1`): all content plus every image as data URLs (cloud and preview images are fetched in); `importFull` restores it through `mediaSet` (so an admin online uploads everything) and publishes. Admin → Game pool → Backup and import, and Admin → Server → Import a backup file.
- Admin access: `canAdmin()` (offline: `VITE_LOCAL_ADMIN`, default on; online: `profiles.is_admin`). The admin button and `data-open="admin"` routing check it.
- Admin panel → Game pool → "Backup and import" copies/pastes the content as JSON.

## Likely next steps
- **Server-authoritative economy:** summons, shop purchases and rewards still run in the browser and the player's own save row is writable by them, so a player could cheat. Move those actions into Supabase Edge Functions (or database functions) that change the save on the server before real money is involved.
- Multiplayer moderation: chat filter, mute/report, rate limits; maybe one channel per area when the plaza gets busy.
- Apple sign-in, password reset, linking a guest to an account.
